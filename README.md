# Крестики-нолики

Консольная игра «Крестики-нолики» на Java. Это рефакторинг игры из домашнего задания 3:
в код добавлены шаблоны проектирования Singleton, Factory, Builder и Dependency Injection.

Что умеет игра:

- поле от 3x3 до 10x10, длину выигрышной линии можно выбрать (от 3 до размера поля);
- играть человек против человека, человек против компьютера или компьютер против компьютера;
- у компьютера три уровня: лёгкий (ходит случайно), средний (выигрывает, если может,
  и закрывает чужую линию), сложный (на поле 3x3 просчитывает партию до конца и не проигрывает);
- несколько партий подряд со счётом, начинающий игрок меняется каждую партию.

## Требования

JDK 17 или новее. Maven нужен только для запуска тестов из командной строки -
IntelliJ IDEA подтянет JUnit сама.

## Запуск

### В IntelliJ IDEA

1. File → Open → выбрать папку проекта (IDEA увидит `pom.xml` и откроет его как Maven-проект).
2. Открыть `src/main/java/tictactoe/Main.java` и нажать зелёную стрелку рядом с `main`.
3. Тесты: правой кнопкой по папке `src/test/java` → Run 'All Tests'.

### Из командной строки, только JDK

macOS / Linux:

```bash
javac -encoding UTF-8 -d out $(find src/main/java -name "*.java")
java -cp out tictactoe.Main
```

Windows (cmd):

```bat
dir /s /b src\main\java\*.java > sources.txt
javac -encoding UTF-8 -d out @sources.txt
java -cp out tictactoe.Main
```

Если в консоли Windows вместо русских букв непонятные символы, перед запуском выполните `chcp 65001`.

### Через Maven

```bash
mvn test            # тесты
mvn package         # сборка target/tic-tac-toe.jar
java -jar target/tic-tac-toe.jar
```

## Как играть

Перед партией программа спрашивает размер поля и кто играет за X и за O.
Если просто нажать Enter, берётся значение по умолчанию (оно в квадратных скобках):
поле 3x3, за X - человек, за O - сложный компьютер.

Ход вводится двумя числами - строка и столбец, считая с 1:

```
     1  2  3
  1  X  .  .
  2  .  O  .
  3  .  .  .

Игрок (X), ваш ход (строка и столбец через пробел): 3 3
```

## Шаблоны проектирования

### Singleton - `Game`

Игра в программе одна, и через неё идёт всё состояние: поле, чей ход, счёт.
Конструктор `Game` закрытый. Экземпляр создаётся один раз методом `Game.init(...)`,
повторный вызов бросает `IllegalStateException`. Дальше игру можно получить из любого места
через `Game.getInstance()`. Оба метода `synchronized`, чтобы при обращении из разных потоков
не получилось двух экземпляров.

Обычно Singleton создаёт себя сам внутри `getInstance()`, но тогда ему пришлось бы самому
создавать поле и игроков, а это противоречит Dependency Injection. Поэтому создание
вынесено в отдельный `init`, которому зависимости передаются снаружи.

Новая партия не создаёт новую игру: `restart()` очищает поле у того же экземпляра,
а счёт сохраняется. Для тестов есть метод `resetInstance()` - он доступен только внутри
пакета `tictactoe.game`, поэтому из основного кода вызвать его нельзя.

### Factory - `PlayerFactory`

Игроки создаются только через `PlayerFactory.create(тип, имя, знак)`. Тип передаётся
значением `PlayerType` или строкой (`"1"`–`"4"`, `"human"`, `"easy"`, `"medium"`, `"hard"`, `"ai"`).
Фабрика решает, какой класс создать (`HumanPlayer` или `AIPlayer`) и с какой стратегией
собрать компьютерного игрока. Остальной код работает только с интерфейсом `Player`
и не знает о конкретных классах.

Чтобы добавить новый вид игрока, нужно дописать значение в `PlayerType` и ветку в фабрике.
Так в фабрику и были добавлены три уровня сложности компьютера: это один класс `AIPlayer`
с разными стратегиями хода.

### Builder - `Board.Builder`

Поле создаётся только через билдер, конструктор `Board` закрытый:

```java
Board board = Board.builder()
        .size(5)           // размер поля, 3–10
        .winLength(4)      // сколько в ряд для победы
        .emptySymbol('-')  // как рисовать пустую клетку
        .mark(2, 2, Mark.X) // заранее поставленный знак
        .build();
```

Все параметры необязательные, по умолчанию получается обычное пустое поле 3x3.
Проверка значений собрана в `build()`: неправильный размер, линия длиннее поля
или занятая дважды клетка дают исключение сразу, и неправильное поле создать нельзя.
Заранее поставленные знаки (`mark`) удобны в тестах: можно сразу получить
нужную позицию, не разыгрывая её ход за ходом.

### Dependency Injection - конструкторы

Классы не создают свои зависимости сами, а получают их в конструкторе:

- `Game(Board, Player, Player, UserInterface)` - поле, двух игроков и интерфейс;
- `HumanPlayer(name, mark, UserInterface)` - откуда читать ходы;
- `AIPlayer(name, mark, MoveStrategy)` - как выбирать ход;
- `PlayerFactory(UserInterface, Random)` - что передать создаваемым игрокам;
- `MinimaxStrategy(MoveStrategy)` - запасную стратегию для большого поля.

Все объекты создаются и связываются в одном месте - в `Main`.
Благодаря этому в тестах вместо консоли подставляется `FakeUI` с заготовленными ответами,
вместо живых игроков - `ScriptedPlayer` с заранее заданными ходами, а в `Random`
передаётся фиксированное зерно, чтобы результат не менялся от запуска к запуску.

## Тесты

В `src/test/java` 41 тест на JUnit 5:

- `BoardBuilderTest`, `BoardTest` - параметры билдера, его проверки, поиск линий по строкам,
  столбцам и диагоналям, копия поля;
- `PlayerFactoryTest` - какой игрок и с какой стратегией получается для каждого типа;
- `HumanPlayerTest` - разбор ввода и повторный вопрос при ошибке;
- `StrategyTest` - средний компьютер выигрывает и блокирует, сложный не попадается
  на вилку и не проигрывает;
- `GameTest` - единственный экземпляр, внедрённые зависимости, победа, ничья, новая партия.
